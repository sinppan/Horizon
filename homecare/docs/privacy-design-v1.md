# 空置房巡检服务系统 · 客户数据隐私与安全设计（V1.0 草案）

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0-draft |
| 配套文档 | `SRS-v1.md`（本文细化其 12.2 节，并新增需求编号 `PRV-xx`） |
| 读者 | 业务负责人、开发、测试、法务顾问 |

> 本文的出发点：这个生意卖的是"把家交给你"的信任，隐私不是合规成本，而是产品本身的一部分。设计目标是**让业主能看见、能控制、能验证**自己的信息是如何被使用的，而不只是后台做好加密。

---

## 1. 设计原则

| 原则 | 含义 | 在本系统中的体现 |
|---|---|---|
| 最小必要 | 只收集服务必需的数据，只在必需的时刻展示 | 巡检员看不到业主姓名电话；入户密码只在打卡后可见 |
| 分级保护 | 不同敏感度的数据用不同强度的措施 | 四级数据分类，各级有明确的存储、传输、展示、保留规则 |
| 按任务授权 | 权限跟着任务走，不跟着角色走 | 巡检员的可见范围由"今天分配给他的任务"决定，而非"他是巡检员" |
| 默认保护 | 默认是最严格的设置，放宽需要业主主动选择 | 默认不拍私人物品区域、默认不生成分享链接、默认 90 天后原片归档 |
| 全程可追溯 | 每一次对敏感数据的访问都有记录 | 访问日志，且业主可以查看"谁在什么时候看过我的房屋信息" |
| 可退出 | 业主随时可以拿走数据、要求删除 | 合同终止后的导出与删除流程 |
| 对业主透明 | 隐私措施不只在后台做，要让业主看得见 | 业主端的"隐私中心"页面 |

## 2. 数据分类分级

所有系统内数据按敏感度分为四级。开发时每个字段、每类文件都必须标明级别，级别决定它适用的规则（第 3–7 章）。

| 级别 | 名称 | 包含的数据 | 泄露后果 |
|---|---|---|---|
| L4 极敏感 | 入户与身份凭证 | 门锁密码、钥匙编号与存放位置、保险箱/贵重物品位置、巡检员身份证号与证件照片、无犯罪记录证明 | 可直接导致入室风险或身份冒用 |
| L3 高敏感 | 可识别到人和家的信息 | 业主姓名、手机号、微信身份、常住城市、紧急联系人、房屋详细地址与经纬度、楼下邻居联系方式、合同金额、照片与视频中的室内画面 | 可定位到具体的人与房、暴露空置状态与生活轨迹 |
| L2 内部敏感 | 服务过程数据 | 检查项结果、读数、异常描述、工单内容、巡检时间与定位打卡、家电与植物清单、服务约定 | 暴露房屋状况与空置规律 |
| L1 低敏感 | 去标识后的运营数据 | 小区名称、房屋编号（系统内部 ID）、模板定义、统计汇总 | 影响有限 |

**关键判断**：

- "这套房长期没人住"本身就是 L3 级信息。任何能推断出空置规律的数据（巡检频次、读数为零、打卡时间）在对外展示时都要谨慎。
- 室内照片和视频整体按 L3 处理，不因为"只是拍墙面"而降级，因为画面里可能出现任何东西。

## 3. 存储层保护

| 编号 | 设计 | 适用级别 |
|---|---|---|
| PRV-01 | 数据库磁盘整体加密（云厂商托管加密），备份文件加密 | 全部 |
| PRV-02 | L4 字段在应用层做字段级加密（AES-256-GCM），密钥由云 KMS 托管，采用信封加密；数据库管理员直接查库看到的是密文 | L4 |
| PRV-03 | L3 中的手机号、身份证号同时存储一份哈希值（加盐）用于查询匹配，明文字段加密存储 | L3 |
| PRV-04 | 加密密钥按年轮换；轮换时旧密钥保留用于解密历史数据，新数据用新密钥 | L4 |
| PRV-05 | 照片、视频存私有对象存储桶，开启服务端加密，桶策略禁止任何公开读；访问只能通过后端签发的签名 URL（照片 ≤ 15 分钟、视频 ≤ 1 小时） | L3 |
| PRV-06 | 原始照片（含完整 EXIF、未压缩）与展示用照片分桶存储；原始桶仅后端服务账号可读，管理端下载原片需二次确认并记录 | L3 |
| PRV-07 | 数据库中不存储照片内容，只存对象存储的路径与元数据 | — |
| PRV-08 | 测试与开发环境不得使用生产数据；需要测试数据时用脚本生成虚构数据 | 全部 |

## 4. 传输层保护

| 编号 | 设计 |
|---|---|
| PRV-09 | 所有接口仅支持 HTTPS（TLS 1.2 及以上），HTTP 请求直接拒绝而非跳转 |
| PRV-10 | 小程序端与后端之间的 L4 数据（入户密码）在 TLS 之上再做一层应用层加密：后端用会话密钥加密下发，小程序端解密后仅在内存中保留，不写入本地存储 |
| PRV-11 | 签名 URL 绑定请求方 IP 段或 token（对象存储支持的范围内），防止链接被转发后他人直接打开 |
| PRV-12 | 企业微信消息中不包含 L3/L4 明文：报告消息只带"小区简称 + 房号后两位 + 状态"，详情通过点击进入小程序后鉴权查看 |

## 5. 访问控制

### 5.1 基本模型

采用"角色 + 任务 + 时间窗"三重判定。角色决定能用哪些功能，任务决定能看哪些房屋，时间窗决定敏感字段何时可见。

| 编号 | 设计 |
|---|---|
| PRV-13 | 巡检员端对业主信息的展示范围：**只显示"业主"二字，不显示姓名、手机号、微信**。巡检员与业主之间不存在直接联系的需要，所有沟通经由管理员 |
| PRV-14 | 巡检员端对地址的展示：任务列表只显示小区 + 楼栋；详细房号在任务详情页展示；经纬度仅用于打卡比对，不展示 |
| PRV-15 | 入户密码的可见时间窗：全职人员任务当天可见（SRS BR-02）；兼职人员打卡通过后可见、提交后立即不可见（SRS BR-02a）。每次展示密码都记录访问日志（PRV-24） |
| PRV-16 | 任务完成 24 小时后，巡检员端对该任务的全部数据（含照片）不可见；本地缓存自动清除（PRV-21） |
| PRV-17 | 管理员分两级：**运营管理员**可处理客户、房屋、排班、工单，但看不到巡检员身份证号和证件照片、看不到业主合同金额；**超级管理员**可看全部。第一版至少把这两级分开 |
| PRV-18 | 批量操作限制：管理端导出客户列表、批量下载照片等操作需超级管理员权限，单次导出记录操作人、时间、范围，并向另一名超级管理员发送通知 |
| PRV-19 | 管理端账号强制开启双因素认证（企业微信扫码 + 密码，或密码 + 短信验证码）；连续 5 次失败锁定 15 分钟 |
| PRV-20 | 所有 token 绑定设备标识，更换设备需重新登录；巡检员端同一账号同一时间只允许一台设备在线 |

### 5.2 设备端保护（小程序）

| 编号 | 设计 |
|---|---|
| PRV-21 | 离线缓存的任务数据在本地加密存储（小程序本地存储本身不加密，需应用层加密，密钥与登录态绑定）；任务提交并同步成功后自动清除；登出时清除全部 |
| PRV-22 | 照片与视频通过小程序相机接口直接拍摄并上传，**不保存到手机相册**；上传完成后清除临时文件 |
| PRV-23 | 入户密码页面、业主档案页面叠加当前登录人姓名 + 时间的半透明水印；在小程序能力范围内禁止截屏（iOS 不支持阻止，仅能检测并记录，见 PRV-25） |

## 6. 审计与可追溯

| 编号 | 设计 |
|---|---|
| PRV-24 | **敏感数据访问日志**：任何对 L3/L4 数据的读取（不只是写入）都记录：谁、何时、从哪个端、看了哪条数据、关联哪个任务。包括：查看入户密码、查看业主联系方式、下载原片、导出列表、查看巡检员证件 |
| PRV-25 | 小程序端检测到截屏事件（系统支持的平台）时上报，记录到访问日志并标记为"疑似截屏" |
| PRV-26 | **异常访问告警**：非任务日访问房屋信息、单日查看超过 N 套房屋的入户信息、非工作时间的批量导出、同一账号短时间内在两地登录，触发超级管理员通知 |
| PRV-27 | 访问日志只增不改，独立存储，普通管理员不可删除；保留 3 年 |
| PRV-28 | **业主可见的访问记录**：业主端"隐私中心"展示"最近 90 天内谁查看过我的房屋信息"，列出时间、人员姓名、角色、对应任务。巡检员在任务当天查看属于正常，会显示"因执行 X 月 X 日巡检任务查看"。这是对业主最直接的信任证明 |

## 7. 照片与视频的专项规则

照片和视频是这个系统里体量最大、也最容易出隐私问题的数据。巡检员进的是别人的家。

### 7.1 拍摄边界

| 编号 | 设计 |
|---|---|
| PRV-29 | 清单模板中每个拍照项标注"拍摄对象"（如"卫生间顶面"），巡检员端在拍照界面显示拍摄提示和取景框引导，减少无关画面 |
| PRV-30 | 建档时业主可在房屋档案中标记"**禁拍区域**"（如书房书桌、衣帽间、保险柜所在位置、照片墙）；巡检员端任务详情醒目展示禁拍区域，对应空间的拍照项附带提示 |
| PRV-31 | 行为规范明确禁止：拍摄人像（含照片墙、相框）、打开抽屉柜门拍摄内部（除非是检查项明确要求的水槽下方柜、电箱）、拍摄文件、证件、账单、药品、私人衣物 |
| PRV-32 | 视频 7 段的拍摄引导中，每段有固定的取景对象和时长上限，不允许自由拍摄"全屋漫游" |
| PRV-33 | 巡检员端提供"**标记为不宜展示**"按钮：拍完后发现画面有不该出现的内容，可标记。被标记的照片仍保存为取证原件，但不进入业主报告，并通知管理员复核 |

### 7.2 处理与展示

| 编号 | 设计 |
|---|---|
| PRV-34 | 展示用照片生成时剥离 EXIF 中的 GPS 信息和设备信息（原片保留用于取证） |
| PRV-35 | 水印内容使用房屋系统编号，不使用地址或业主姓名 |
| PRV-36 | 管理员在推送报告前可以抽查照片，并对单张照片做"仅取证，不展示"处理 |
| PRV-37 | 报告分享链接（SRS FR-RPT-03）默认关闭，业主主动开启后才生成；链接有效期 7 天（比 SRS 原设 30 天更短），业主可随时失效；分享页不含地址、不含读数曲线、不含工单报价 |
| PRV-38 | 第二版规划：接入图像识别，自动检测人脸、证件、文字密集区域并打码或拦截 |

### 7.3 视频剪辑环节的管控（第一版的最大漏洞）

成片由人工在剪映等工具中剪辑，意味着**原片会离开系统、进入某个人的手机或电脑**。这是第一版隐私链条上最弱的一环，必须有明确的流程约束：

| 编号 | 设计 |
|---|---|
| PRV-39 | 剪辑只能由管理员（而非巡检员）执行；巡检员上传原片后本地立即清除（PRV-22） |
| PRV-40 | 剪辑使用公司专用设备（手机或电脑），不使用个人设备；设备开启锁屏密码与磁盘加密 |
| PRV-41 | 原片从管理端下载时记录日志（PRV-24）；成片上传后，管理端提示"请确认已删除本地原片与工程文件"，操作人勾选确认，记录在案 |
| PRV-42 | 剪辑设备上不登录任何云盘、相册同步服务；剪映等工具关闭云端草稿同步 |
| PRV-43 | 第二版目标：服务端按模板自动拼接 7 段原片生成成片，彻底消除人工剪辑环节 |

## 8. 数据生命周期

| 阶段 | 规则 | 编号 |
|---|---|---|
| 收集 | 业主首次进入小程序展示隐私政策，逐项说明收集什么、为什么、保留多久；对 L4 数据（入户密码）和精确位置另行**单独同意**（PIPL 对敏感个人信息的要求） | PRV-44 |
| 收集 | 巡检员入职时对身份证、无犯罪记录证明的收集签署单独同意书；明确用途仅限准入审核 | PRV-45 |
| 使用 | 数据仅用于提供巡检服务、处理异常、生成报告；不用于营销画像、不与第三方共享（企业微信、云厂商等处理者除外，见第 9 章） | PRV-46 |
| 保留 | 照片保留合同期 + 1 年；视频原片 90 天后转低频存储、180 天后删除（成片保留同照片）；访问日志 3 年；巡检员证件照片在其离职后 6 个月删除，仅保留"已核验"标记 | PRV-47 |
| 合同终止 | 终止后 30 天内，业主可在小程序申请**一键导出**全部报告、照片、视频（打包下载链接，有效 7 天）；导出后可申请**删除** | PRV-48 |
| 删除 | 业主申请删除后 15 个工作日内完成：个人身份信息（姓名、手机、微信、地址）彻底删除；巡检记录做匿名化处理（房屋编号替换为随机值、去除所有可关联字段）后保留用于运营统计；照片视频全部删除，包括对象存储的历史版本 | PRV-49 |
| 删除 | 备份中的数据随备份周期（30 天）自然过期；删除请求记录保留，以证明已执行 | PRV-50 |
| 法律例外 | 处于纠纷、诉讼或保险理赔中的记录，可暂停删除至事项结束，需超级管理员标记并记录原因 | PRV-51 |

## 9. 第三方与供应商

系统依赖的外部服务都会接触到部分数据，需要逐个评估。

| 服务 | 接触到的数据 | 级别 | 控制措施 |
|---|---|---|---|
| 云服务商（服务器、数据库、对象存储、KMS） | 全部 | L4 | 选择境内合规大厂；开启托管加密；L4 字段应用层加密后云厂商也无法读取明文；签订数据处理协议 |
| 企业微信 | 业主微信身份、群消息内容 | L3 | 消息中不含 L3/L4 明文（PRV-12）；小程序订阅消息模板只填状态和日期 |
| 短信服务商 | 手机号、验证码、紧急通知文案 | L3 | 文案不含地址与具体异常内容；仅在企业微信失败时兜底使用 |
| 地图服务 | 房屋经纬度（导航时） | L3 | 仅在巡检员点击导航时调用；使用小程序的系统地图跳转而非把坐标传给第三方 API 存储 |
| 电子签（若用） | 合同内容、业主身份 | L3 | 第一版不集成，合同作为附件上传系统 |
| 剪辑工具 | 视频原片 | L3 | 见 7.3 节 |
| CDN | 展示用照片与成片 | L3 | 仅分发签名 URL 的内容，CDN 层不缓存未鉴权请求的响应；海外节点仅在确有海外业主时开启 |

**不允许的做法**：用微信个人号、QQ、公共网盘、邮件传输任何照片视频或客户名单；用 Excel 在个人电脑上维护客户表。

## 10. 人员与流程

技术措施能防住外部，防不住内部。这个生意最大的隐私风险是人。

| 编号 | 设计 |
|---|---|
| PRV-52 | 所有接触系统的人员（巡检员、管理员）签署保密协议，内容包括：不记录、不拍摄、不转述客户信息，离职后持续有效；违约责任与赔偿条款 |
| PRV-53 | 入职培训包含隐私专项：什么能拍什么不能拍、为什么巡检员看不到业主姓名、发现自己误拍了怎么办、被业主邻居询问时如何回答 |
| PRV-54 | 巡检员离职流程：停用账号（即时）→ 回收公司设备 → 确认个人手机无残留（当面检查相册与微信文件）→ 签离职保密确认 |
| PRV-55 | 管理员离职流程：停用账号 → 轮换其可能接触过的所有共享凭证 → 检查其名下的导出记录 → 回收剪辑设备并重置 |
| PRV-56 | 每季度由超级管理员抽查访问日志：随机抽 20 条入户密码访问记录核对是否对应当天任务；抽 20 组照片核对是否有越界拍摄 |
| PRV-57 | 办公场所不打印客户名单、房屋信息；确需打印的（如钥匙领用登记）使用房屋编号而非地址 |

## 11. 合规要点（中国大陆）

依据《个人信息保护法》《数据安全法》《网络安全法》及小程序平台规则，第一版必须满足：

| 编号 | 要求 | 落实方式 |
|---|---|---|
| PRV-58 | 隐私政策公示 | 小程序首次进入展示，"隐私中心"可随时查看；内容涵盖收集范围、目的、方式、保留期限、第三方、用户权利、联系方式 |
| PRV-59 | 单独同意 | 入户密码、精确位置、巡检员身份证属于敏感个人信息，需在通用同意之外单独弹窗确认 |

| PRV-61 | 用户权利响应 | 查阅、复制、更正、删除、撤回同意，均通过小程序"隐私中心"发起，15 个工作日内响应 |

## 12. 业主端「隐私中心」：把隐私做成看得见的产品

这是整个设计里最值得投入的部分。业主对隐私的焦虑无法靠"我们有加密"来消除，要让他们**亲眼看到控制权在自己手里**。

| 编号 | 功能 | 优先级 |
|---|---|---|
| PRV-65 | **访问记录**：最近 90 天谁、何时、因什么任务查看过我的房屋信息（PRV-28） | P0 |
| PRV-66 | **禁拍区域管理**：查看和修改建档时设置的禁拍区域（PRV-30） | P0 |
| PRV-67 | **服务人员信息**：显示当前负责我房屋的巡检员姓名、照片、已核验标记（身份证已核验、无犯罪记录已核验、入职日期），不显示其联系方式 | P0 |
| PRV-68 | **分享管理**：查看已生成的分享链接，一键失效（PRV-37） | P1 |
| PRV-69 | **数据导出**：申请打包导出全部数据（PRV-48） | P0 |
| PRV-70 | **数据删除**：合同终止后申请删除（PRV-49） | P0 |
| PRV-71 | **隐私政策与同意记录**：查看自己何时同意了哪个版本 | P0 |
| PRV-72 | **年度隐私报告**：随年度报告附一页：全年入户次数、访问记录汇总、照片数量、已删除的原片数量、未发生的安全事件 | P1 |

**对外的隐私承诺**（可写入服务协议和宣传材料）：

1. 巡检员不知道您是谁：他们看不到您的姓名和联系方式。
2. 入户密码按次可见：巡检员只在到达您家门口打卡后才能看到密码，离开后立即失效。
3. 您能看到每一次查看：谁在什么时候看过您家的信息，您随时可查。
4. 您划定不拍的地方，我们不拍。
5. 您随时可以带走并删除全部数据。
